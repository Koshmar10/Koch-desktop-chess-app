# Koch

Desktop chess app — Tauri 2 + React 19 + Rust, with an embedded engine, a Stockfish
subprocess for analysis, SQLite history, and an AI position assistant.

This is a **deliberate rebuild** of a previous implementation, started 2026-08-16.

## Background

**Eval sign convention.** §3 of [KOCH-HANDOFF.md](KOCH-HANDOFF.md) records a
sign-convention landmine in the eval pipeline that has already caused one wrong fix.
Read it before touching eval code.

reference** until feature parity is reached. All file:line references in the handoff

**AI assistant scenarios.** [docs/assistant-scenarios.md](docs/assistant-scenarios.md) is

[docs/assistant-scenarios-proposed.md](docs/assistant-scenarios-proposed.md) holds five

reconcile it with the working list before building tools from it.

## How work is organised

- Tickets live in Lira (project key `KOCH`), one ticket per shippable slice.
- Feature branch per ticket → PR into `main` → CI green before merge. No direct pushes.
- Conventional commits.
- Engine changes require tests. Frontend changes require lint + typecheck to pass.

## Quality bar

- `koch-engine` is tested hard: perft, FEN round-trip, castling, en passant, promotion,
  pin legality. This crate has no Tauri dependency and must stay that way.
- Persistence and command layers get integration tests.
- Frontend gets ESLint + `tsc`; unit tests only for pure logic.
- CI runs `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`, Prettier,
  `eslint`, `tsc --noEmit` and `vitest` on every PR.

## Conventions

A standard that isn't written down can't be checked in review. Each rule says why, so
an exception can be argued on the same terms.

### Frontend

- **Where code lives.** `src/api/` is IPC only: command wrappers and `events.ts`.
  `src/lib/` holds pure domain tables and helpers, and gets unit tests.
  `src/components/` is shared UI; `src/sections/<screen>/` is one screen's own.
  *Why:* you know where to look before you open anything.
- **Components are arrow functions, without `React.FC`.** Write `const X = (props: XProps) => …`.
  Hooks and helpers follow the same shape; there are no `function` declarations.
  *Why:* `React.FC` adds nothing the props annotation doesn't, and one shape makes every
  file read the same.
- **An exported component declares `interface XProps`** right above it. A small
  file-internal component may type its props inline.
  *Why:* the props are the component's API. A named interface is where its comments go,
  and it's the name a type error points at.
- **Exports.** A file with one component default-exports it. A file holding a family
  uses named exports: `buttons.tsx`, `controls.tsx`, `chips.tsx`, `InteractiveRow.tsx`,
  `StatGraphs.tsx`, `settings/Section.tsx`.
  *Why:* you know how to import a file without opening it.
- **Types live in `.ts` files.** A shared type goes in the section's `types.ts`, or in the
  `lib/` module it belongs to, never in a component file. Types for IPC payloads come
  from `src/api/bindings` (generated by ts-rs) and are never hand-copied.
  *Why:* `TimelineMove`, exported from `Analyzer.tsx`, made the timeline chart import the
  screen that renders it, which is a circular import.
- **Constant names carry their unit.** Module-level constants use `SCREAMING_SNAKE`:
  `_CLASS` for Tailwind class strings, `_PX` for pixel sizes (`ICON_SIZE_PX`,
  `BOARD_SIZE_PX`). Counts and ratios get no suffix. Local variables spell the word out:
  `pillClass`, not `pillCls`.
  *Why:* `BOARD_SIZE` (8 squares) next to `BOARD_SIZE_PX` (720) says which one you have.
- **Tailwind classes are written out whole,** never built as `` `bg-${color}` ``. Map a
  value to a full class with a `Record`.
  *Why:* Tailwind only generates classes it finds spelled out in the source.
- **Backend events go through `useAppEvent`.** Never call `listen` directly. Event names
  and payloads are listed once, in `api/events.ts`, which mirrors `app/events.rs`.
  *Why:* a misspelled name or the wrong payload type then fails to compile.
- **Reuse the shared pieces before writing class strings:** `DialogCard`, the
  `Primary`/`Outline`/`GhostButton`s, `TooltipButton`, `PanelSection`, `EmptyNote`, and
  the controls.
  - Prefer a base component with named wrappers (`PlainRow`/`CardRow`) over a
    `variant` prop.
  - Prefer icons to text labels where the meaning survives.
- **Call shared utilities at the use site.** Don't alias one in a local `const` first.

### Backend

- **Commands return `Result<T, AppError>`.** `?` converts the error through `AppError`'s
  `From` impls. A new error source gets a `From` impl, not a `.map_err` at each call.
- **Services return `rusqlite::Result`.** `Ok(None)` means "nothing there" or "nothing
  new", for example a duplicate game. The caller decides whether an error fails the
  command or is logged; nothing is swallowed with `.ok()` or `if let Ok(..)`.
  *Why:* a failed import used to be reported to the user as "already in your library".
- **Multi-statement writes run in one transaction:** `unchecked_transaction()` … `commit()`.
  *Why:* a game row whose moves failed to save is a game the analyzer can't replay.
- **Reads are strict.** A stored value that doesn't parse is an error naming the column
  (see `db/columns.rs`), never a quiet default.
- **Bind the lock to a name and scope it.** Write `let conn = db.lock()?;` inside a block
  that ends before any `.await`. Don't use `&*db.lock()?` temporaries.
  *Why:* a guard held across an `.await` makes the future non-`Send`.
- **Background work is a fallible `async fn` with one logging site.** See
  `spawn_engine_reply` → `play_engine_reply`, and the analysis worker → `analyse_and_save`.
  Best-effort side work, such as the rating update or the opening label, is logged where
  it's called, with a comment saying why it doesn't fail the command.
- **No duplicated literals.** Use `app::ENGINE_PATH` for Stockfish, and
  `FenString::default()` for the start position. A closed set of values stored in a TEXT
  column is an enum with `as_db_str` / `from_db_str`.
- **Everything that crosses IPC derives `TS`** and is exported to `src/api/bindings`.
